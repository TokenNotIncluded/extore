# 一卡一文本

处理方式选择「一卡一文本 · 自动交付」。保存商品后，在卡密页选择规格，粘贴交付文本或导入 UTF-8 文本文件。无需填写顾客参数、定义处理步骤或运行处理器。

每个非空行生成一张密码学安全的随机卡密，并固定关联该行文本和选择的规格。忽略空行，去掉行首尾空白，兼容 UTF-8 BOM、LF 与 CRLF；本次导入完全相同的行只生成一张卡密。保留大小写、行内空格和文本本身，不执行其中的命令或链接。后续导入可以再次创建相同文本，支持有意补货。

一次最多导入 2 MiB、生成 1,000 张卡密，每行最多 10,000 字符。店铺、全站存储额度和磁盘保留空间同样适用；导入前检查整个批次，额度不足不会创建半批卡密。

生成后可以一键复制全部卡密、下载卡密文本，或者下载包含每张卡密与交付文本对应关系的 JSON。原文只在本次创建响应中显示，离开页面后不能从卡密管理或事件记录找回。对应表同时包含访问凭据与交付原文，应保存在自己的受控位置。

顾客验码后直接领取绑定的文本，不进入处理队列。商品可选择重复查看或仅领取一次，顾客也可主动销毁交付。未兑换的文本按店铺和卡密身份加密保存；完成交付后清除原始分配副本。一次领取或销毁会清除领取页内容并释放其存储额度。已经下载的副本和既有服务器备份不受该操作撤回。

## HTTP 接口

`POST /api/manage/cards/import-text`（店主管理也可使用 `/api/admin/cards/import-text`）。使用现有管理会话或已授权的 CLI 设备，必须具有该商品的 `cards.manage` 权限。

```json
{
  "product_id": "商品 ID",
  "variant_id": "default",
  "text": "第一条文本\n第二条文本\n第一条文本\n",
  "label": "六月补货",
  "expires": null
}
```

响应的 `codes` 是本次生成的卡密；`items` 按导入顺序列出 `{ "code": "随机卡密", "content": "对应文本" }`。`batch_id` 可以用于现有卡密库存筛选。统计字段：

| 字段 | 含义 |
| --- | --- |
| `stats.lines` | 输入行数，末尾换行不另算一个空行 |
| `stats.blank` | 忽略的空行数 |
| `stats.duplicates` | 本次合并的重复行数 |
| `stats.created` | 实际生成卡密数 |

普通按数量制卡接口不能为一卡一文本商品发行没有内容的空卡密。商品已经发行卡密后，不能更换处理方式、交付类型、查看规则或输出结构；描述、图片和规格展示信息仍按现有商品编辑规则管理。
