# 进度看板

在商家后台或商品管理页选择「进度看板」，查看各商品的流水线、任务状态、处理者负载和最近上报的进度。这里没有任务详情入口，也不读取顾客需求、处理说明、交付内容或附件。

店主查看本店；平台管理员必须先选定一家店铺；商品管理者只能查看授权商品。不同商品的队列仍然独立，看板只是汇总展示，不改变领取和处理规则。

## 看什么

- 默认查看未处理完的任务，已完成、拒绝和销毁的任务放在「已处理」。
- 按商品查看排队、处理中、等待顾客和需要重试的数量。
- 查看处理者的进行中任务、已处理数量和最后一次任务更新。已处理包括完成、拒绝和销毁，不等于成功交付数量。
- 查看任务的实际百分比、完成步骤数量、队列位置和更新时间。

步骤只显示序号和状态，不显示自定义步骤名称。处理者名称来自已配置的管理身份；它表示领取任务的管理身份，不保证能区分共享同一身份的浏览器、CLI 或实际运行进程。「最后更新」不等于在线状态，不提供推测的完成时间。

有序处理步骤以任务自己的快照为准；没有步骤计划时显示处理者上报的百分比。分支任务流程按实际执行状态显示，不把未知的后续分支编造为固定完成比例。

页面自动刷新，可暂停或手动刷新；页面隐藏、退出或切换标签后停止轮询。刷新失败时提示旧数据和最近一次成功更新时间。任务较多时分页，数量汇总不因当前页截断而减少。

## 只授予进度查看权限

创建商品管理链接时选择「只看进度看板」，授予独立的 `queue.monitor` 权限。这个权限不允许读取任务参数、处理说明、结果、附件，也不允许领取任务或修改进度。

已有 `queue.view` 权限包含更详细的队列读取能力，也可以查看进度看板。升级不会自动向旧授权添加新权限；处理任务仍须具备 `queue.view` 和 `queue.process`。

AI 可以通过设备码主动申请只读看板：

```sh
extore manage login --device-code --origin https://extore.example --product PRODUCT_ID --permissions queue.monitor --client-name '进度观察 Bot' --no-wait
```

把公开批准地址、设备码和设备指纹交给店长，店长核对并批准后，使用相同命令去掉 `--no-wait` 完成登录。不发送管理链接或私钥。

## CLI 与 WebMCP

要求 Extore **0.9.0+**：

```sh
extore admin board
extore admin board --product PRODUCT_ID --view processed
extore admin board --shop SHOP_ID
extore manage board --origin https://extore.example
extore manage board --product PRODUCT_ID
```

店主 CLI 固定到自己的店铺；平台管理员必须明确 `--shop`。商品 CLI 保存多个独立授权时，可汇总各个获准商品的进度，每个请求分别校验权限，不合并不同授权的能力。

原生 WebMCP 提供 `extore_progress_board`，沿用当前浏览器身份和商品范围。工具和 CLI 使用同一个只读接口，只返回看板数据。具备进度权限并不意味着具备商品配置、队列处理或文件访问权限。

## 接口

`GET /api/manage/progress-board` 支持 `shop_id`、`product_id`、`view=active|processed`、`limit=1..200`（默认 100）和 `offset=0..1000000`。响应版本为 `extore.progress-board.v1`。汇总计数覆盖授权范围，不仅是当前页；工人列表展示正在处理任务的身份和当前页涉及的身份。

响应包含店铺和商品名称、固定任务状态计数、匿名化的处理者标识、管理身份名称、进度百分比、步骤序号、时间和分页信息。它不返回卡密、领取凭证、邮箱、设备密钥、需求、处理说明、自定义步骤文字、交付结果、文件名或任务流程内部变量。接口不会为了展示看板冻结或修改任务计划。
