# 0.8.0 更新说明

本轮把一次兑换扩展为可选的分步任务，并保留既有商品、卡密、Webhook v1 和认证授权流程。本文说明代码接口与兼容性；发布、部署和真实业务验收须按[验证指南](../acceptance.md)分别核实。

- **商品任务流程**：输入、处理、展示、结束节点，有限分支、前序结果引用、显式开始和时限。图与执行配置按发行卡密冻结；当前顾客视图和处理权限不暴露整图私密数据，旧 epoch / attempt 不能覆盖新节点。
- **文本库存**：按商品规格粘贴或导入 UTF-8 文本，每个非空行生成随机卡密并绑定文本；同次重复行去重，整批额度不足不创建半批。原卡和对应表只在发行时返回。
- **字段与交付**：下拉选项、是／否、单张图片与有序图片集合，沿用字符串 API。图片逐个校验、计量和绑定，文件仍按一次领取、重复查看与销毁规则处理。
- **私有 Worker v2**：签名绑定店铺、商品、任务、尝试、节点、epoch、action_id，以及方向和准确请求目标。当前输入加密派发，结果与附件有独立幂等回执，兼容 v1 服务。
- **签名兑换路由**：浏览器本地校验 EXR1 路由卡，明确跳转到固定发行站；入口站后端不接收下游完整卡密，普通旧卡不会逐站试探。
- **网页与 CLI 批量兑换**：逐卡校验与预览，按商品、规格及兼容冻结输入分组，共用文字输入、各卡独立上传。坏码或单项提交错误不阻断其他卡；流程卡逐张明确开始。CLI `--atomic` 保留旧同商品整批事务模式。
- **原生 WebMCP 流程操作**：只按当前步骤提供题目、字段和允许的动作，不导出整图或历史答案；路由卡从可见页面输入框读取，不作为工具参数传入。
- **AI CLI 领取**：`manage next` 将等待与领取合成原子操作，返回当前任务和节点。`--watch` 等到首批任务后输出并退出，持续机器人由接入方循环安排；响应丢失先恢复同一请求，不自动另领一单。

## 升级与边界

普通商品 `task_flow:null` 保持一次填写的旧流程。没有发行流程快照的旧卡不继承商品后来新增的图。普通 `/api/exchange`、`/api/redeem` 的旧批量整组语义保留；新 partial 端点是 `/api/batch/*`，调用方需检查每项结果。CLI 的真实支持和命令参数以[顾客 CLI](../cli-customer.md)与安装版本的 help 为准。

现有店铺隔离、Passkey、2FA、设备码、授权快照、会话审计和只写秘密继续适用。短期敏感字段只可用于流程文本输入；不能用于普通商品参数、显示、分支或最终输出。固定本地处理器仍受原离线 sandbox 限制，不能借图启用任意命令、写盘或网络。

处理超时或网络响应丢失不能证明外部动作未执行；支付与发货必须由可信执行端持久幂等并核实真实结果。Extore 不收款，也不内置持续运行的通用 AI。接口、合成测试或预设模板不代表真实 AI 文档／PPT 质量、实际支付或第三方交付已经验收。
